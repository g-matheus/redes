Atividade 1 • HTTPS

tls-apache2.sh

Instala Certbot, ativa HTTPS e testa a renovação dos certificados.

Antes de executar

Configure DNS para os quatro nomes. O registro do Certbot não inclui e-mail.

Script gerado completo

tls-apache2.sh
#!/bin/bash

set -Eeuo pipefail
export DEBIAN_FRONTEND=noninteractive

source "$(dirname "$0")/setup.conf"

echo "==> Configuring TLS ..."
echo
echo "-> Installing certbot ..."
apt install -y certbot python3-certbot-apache
echo "-> Configuring TLS certificates ..."
certbot --apache \
    --non-interactive \
    --agree-tos \
    --redirect \
    --register-unsafely-without-email \
    -d "$DOMAIN_NAME" \
    -d "www.$DOMAIN_NAME" \
    -d "$SUBDOMAIN1.$DOMAIN_NAME" \
    -d "$SUBDOMAIN2.$DOMAIN_NAME"
echo "-> Testing certificate renewal ..."
certbot renew --dry-run
systemctl reload apache2
echo
echo "==> Apache2 installation and TLS configuration completed successfully!"

Comandos e parâmetros

Linhas comuns do Bash e echo

#!/bin/bash seleciona o interpretador Bash. set -Eeuo pipefail encerra em falhas (-e, com exceções do Bash), propaga uma eventual trap ERR a funções e subshells (-E; subshell é um shell filho, trap é uma ação definida para ocorrer diante de um evento, e este script não define uma trap ERR), detecta variáveis ausentes (-u) e falhas em qualquer comando de um pipeline (pipefail; pipeline é a ligação de comandos com |). export DEBIAN_FRONTEND=noninteractive passa ao APT a preferência de instalação sem perguntas interativas. echo exibe mensagens de status; sem argumentos, gera uma linha em branco.

source e variáveis do domínio

source lê um arquivo no shell atual para disponibilizar as variáveis nele definidas. O script localiza setup.conf na própria pasta usando $(dirname "$0"): $0 é o caminho de execução, dirname retorna sua pasta e $(...) substitui o comando pelo resultado. DOMAIN_NAME, SUBDOMAIN1 e SUBDOMAIN2 são variáveis configuradas nesse arquivo.

apt install -y certbot python3-certbot-apache

apt instala pacotes dos repositórios do Ubuntu; install indica a operação; -y confirma automaticamente. certbot é o cliente do Let's Encrypt para obter e renovar certificados TLS. python3-certbot-apache é a integração do Certbot com Apache, usada para localizar e ajustar os VirtualHosts.

certbot --apache

Executa o Certbot com o plugin Apache. Ele solicita certificados à autoridade certificadora Let's Encrypt, comprova que o servidor controla cada nome de domínio e configura os VirtualHosts para usar os certificados. TLS é o protocolo criptográfico que protege a conexão HTTPS; HTTPS é HTTP protegido por TLS. Um certificado associa os nomes solicitados à chave pública do servidor. DNS (Sistema de Nomes de Domínio) traduz esses nomes para endereços IP. A validação HTTP depende de DNS correto e acesso externo ao servidor.

--non-interactive e --agree-tos

--non-interactive impede perguntas durante a execução; --agree-tos registra a aceitação dos termos de serviço da autoridade certificadora. São opções longas do Certbot; os dois hífens fazem parte da sintaxe.

--redirect

Pede ao plugin Apache para configurar um redirecionamento HTTP para HTTPS: pedidos sem criptografia na porta 80 recebem uma resposta que leva o navegador à versão HTTPS, normalmente na porta 443. Um redirecionamento não substitui a abertura das portas na nuvem e no firewall do servidor.

--register-unsafely-without-email

Registra a conta do Certbot sem endereço de e-mail. A opção “unsafely” alerta que a autoridade não terá como enviar avisos de expiração ou problemas da conta. A renovação automática continua sendo configurada, mas o operador precisa acompanhar se ela funciona.

-d

-d (abreviação de --domains) adiciona um nome DNS ao pedido; pode ser repetido. “Hostname” é o nome de um host na rede, como blog.exemplo.com. O certificado pedido cobre DOMAIN_NAME, www.DOMAIN_NAME e os dois subdomínios. Todos precisam resolver para o IP público e estar configurados no Apache.

certbot renew --dry-run

renew tenta renovar certificados próximos do vencimento; --dry-run executa um ensaio contra o ambiente de testes da autoridade certificadora, sem substituir os certificados de produção. É uma simulação de fluxo de renovação, não uma renovação real.

systemctl reload apache2

systemctl envia uma ação ao gerenciador de serviços systemd; reload pede ao serviço apache2 para reler configurações sem encerrar e iniciar todo o processo. Isso não reinicia o servidor nem a instância na nuvem.
