Publicação no subdomínio 1

Faz o deploy do site definido no repositório remoto Git configurado em setup.conf.

Script

deploy-subdomain1.sh

Comandos e parâmetros

Linhas comuns do Bash

#!/bin/bash seleciona o interpretador Bash. set -Eeuo pipefail encerra diante de falhas (-e, com exceções do Bash), estende uma eventual trap ERR a funções e subshells (-E; subshell é um shell filho, trap é uma ação definida para ocorrer diante de um evento, e este script não define essa trap), detecta variáveis não definidas (-u) e faz falhar pipelines se qualquer comando falhar (pipefail; pipeline é uma sequência ligada por |). export DEBIAN_FRONTEND=noninteractive configura o ambiente para instalações não interativas de pacotes; este script não instala pacotes, então o Git precisa estar instalado previamente.

source "$(dirname "$0")/setup.conf"

source executa o arquivo no shell atual para importar as variáveis. $0 contém o caminho usado para chamar o script; dirname obtém a pasta desse caminho; $(...) substitui o comando pelo resultado. A barra / junta essa pasta a setup.conf, permitindo localizar a configuração mesmo quando o script é chamado de outro diretório.

FULL_DOMAIN

É uma variável do shell: o sinal = atribui um valor sem espaços em volta; ${SUBDOMAIN1} e ${DOMAIN_NAME} inserem os valores de configuração. O ponto separa o rótulo do subdomínio do nome do domínio, formando, por exemplo, blog.exemplo.com.

WEB_DIR

Armazena o caminho de destino do site, como /var/www/blog.exemplo.com. /var/www é o diretório convencional para conteúdo web no Ubuntu; o restante do caminho é criado com base no domínio completo. O prefixo / indica caminho absoluto.

echo

Imprime texto no terminal e termina a linha. As aspas duplas agrupam o texto e permitem expandir variáveis como ${WEB_DIR} e ${FULL_DOMAIN}. O operador > dentro de uma mensagem entre aspas é apenas texto, não redirecionamento. O comando git clone aparece fora do echo e por isso é executado.

Pré-requisito: Git instalado

O script chama git clone, mas não instala o Git. Se o comando git ainda não estiver disponível no servidor, instale-o antes com sudo apt-get install -y git. Execute o script de publicação como administrador com sudo, conforme a instrução da página inicial.

rm -rf

Remove o diretório de destino e todo o seu conteúdo. Neste script, é executado antes do clone para substituir completamente a publicação anterior. A opção -r remove diretórios recursivamente e -f não solicita confirmação. Por isso, confira o domínio e faça backup antes de executar o script com sudo.

git clone

git é o sistema de controle de versão; clone baixa uma cópia de um repositório e seu histórico. O primeiro argumento, "$SUBDOMAIN1_SITE_REPO_URL", é a URL do repositório configurada em setup.conf; o segundo, "$WEB_DIR", é a pasta de destino. As aspas preservam cada valor como um único argumento mesmo que contenha caracteres especiais. O diretório é recriado pelo clone após a remoção feita pelo comando anterior. O script não instala o Git; instale-o antes, se necessário, com sudo apt-get install -y git.

chown -R www-data:www-data

Altera recursivamente o proprietário e o grupo de todos os arquivos clonados para www-data, a conta usada pelo Apache no Ubuntu. Isso permite que o servidor web leia o conteúdo publicado.

Mensagem final

O echo informa o endereço montado com ${FULL_DOMAIN}. A mensagem impressa pelo script usa http://. Depois da execução de tls-apache2.sh, o Certbot configura HTTPS e redirecionamento para HTTPS. O VirtualHost criado por apache2.sh usa /var/www/$FULL_DOMAIN como DocumentRoot, isto é, a pasta que o Apache serve para esse subdomínio.

Relação com este site

Este script usa Git para baixar o repositório indicado e colocá-lo no primeiro subdomínio; não copia automaticamente esta pasta local. Para baixar um template e enviá-lo por SCP ao segundo subdomínio, siga a página de publicação no subdomínio 2.
