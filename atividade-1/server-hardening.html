server-hardening.sh

Configura hardening de SSH, firewall e Fail2ban.

Script

server-hardening.sh
#!/bin/bash

set -Eeuo pipefail
export DEBIAN_FRONTEND=noninteractive

echo "==> Updating packages..."
echo
apt-get update
apt-get upgrade -y
echo
echo "==> Configuring automatic updates..."
echo
apt-get install -y unattended-upgrades
cat > /etc/apt/apt.conf.d/20auto-upgrades <<'EOF'
APT::Periodic::Update-Package-Lists "1";
APT::Periodic::Unattended-Upgrade "1";
EOF
systemctl enable --now apt-daily.timer
systemctl enable --now apt-daily-upgrade.timer
echo
echo "==> Configuring SSH hardening..."
echo
sed -i -E "s/^#?PasswordAuthentication.*/PasswordAuthentication no/" "/etc/ssh/sshd_config"
sed -i -E "s/^#?PermitRootLogin.*/PermitRootLogin no/" "/etc/ssh/sshd_config"
sed -i -E "s/^#?X11Forwarding.*/X11Forwarding no/" "/etc/ssh/sshd_config"
echo
echo "==> Configuring Firewall (UFW)..."
echo
apt-get install -y ufw
ufw default deny incoming
ufw default allow outgoing
ufw limit ssh
ufw --force enable
echo
echo "==> Restarting SSH service..."
echo
systemctl restart ssh
echo
echo "==> Installing Fail2ban..."
echo
export PYTHONWARNINGS="ignore::SyntaxWarning"
apt-get install -y fail2ban
systemctl enable --now fail2ban
unset PYTHONWARNINGS
echo
echo "==> Done! Restarting server ..."
reboot

Comandos e parâmetros

echo e linhas em branco

echo escreve uma mensagem no terminal. Quando aparece sem texto, apenas imprime uma linha em branco para separar etapas; não altera configuração nem executa outro comando.

set -Eeuo pipefail

set altera opções do Bash. -e encerra o script quando um comando falha (com exceções em certas condições); -E faz um eventual tratamento ERR também valer em funções e subshells. Uma trap é uma ação definida para ocorrer quando acontece um evento; este script não define uma trap ERR. Um subshell é um shell filho iniciado para executar uma parte do trabalho. -u trata o uso de variável não definida como erro. pipefail faz um pipeline retornar falha se qualquer comando dele falhar, não apenas o último. Um pipeline é uma sequência ligada por |; este script não usa nenhum.

DEBIAN_FRONTEND=noninteractive

Define uma variável de ambiente usada pelos instaladores Debian, incluindo o APT. noninteractive pede que os pacotes não abram perguntas interativas durante a instalação. export torna a variável disponível aos comandos filhos do shell. O APT é o sistema de gerenciamento de pacotes do Ubuntu; os pacotes são programas e arquivos instaláveis.

apt-get update / apt-get upgrade -y

apt-get é a interface de linha de comando do APT. update baixa os índices dos repositórios (catálogos de pacotes disponíveis); não instala atualizações. upgrade instala versões atualizadas dos pacotes instalados quando isso não exige remover pacotes. -y responde “sim” às confirmações. O hífen em apt-get faz parte do nome do comando.

unattended-upgrades

É o pacote que instala o serviço de atualizações de segurança automáticas do Ubuntu. “Unattended” significa que a tarefa agendada pode rodar sem alguém responder a cada pergunta no terminal; as diretivas gravadas no arquivo de configuração ativam as tarefas periódicas.

cat > ... <<'EOF' e 20auto-upgrades

cat lê o texto recebido e > redireciona a saída para o arquivo, criando-o ou substituindo seu conteúdo. <<'EOF' inicia um heredoc: o texto entre essa linha e a linha que contém apenas EOF vira entrada do comando. As aspas impedem a expansão de variáveis e substituições nesse bloco. /etc/apt/apt.conf.d/ guarda configurações do APT; 20auto-upgrades é o arquivo criado. As diretivas APT::Periodic::Update-Package-Lists e APT::Periodic::Unattended-Upgrade, com valor "1", ativam as tarefas periódicas correspondentes. Os dois-pontos fazem parte da sintaxe das diretivas do APT.

systemctl enable --now

systemctl controla serviços e unidades do systemd, o gerenciador de serviços do Ubuntu. enable configura uma unidade para iniciar automaticamente; --now também a inicia imediatamente. apt-daily.timer e apt-daily-upgrade.timer são timers (unidades que agendam tarefas) do APT: um atualiza os índices e o outro executa atualizações automáticas.

sed -i -E e as expressões de configuração SSH

sed transforma texto linha a linha. -i grava a alteração diretamente no arquivo (“no lugar”); -E habilita expressões regulares estendidas, um padrão para localizar texto. Em s/padrão/substituição/, s significa substituir, a primeira barra separa o padrão e a segunda separa a substituição. ^ significa início da linha, #? aceita zero ou um sinal de comentário #, e .* corresponde ao restante da linha. Assim as três regras substituem, estejam comentadas ou não, as diretivas PasswordAuthentication, PermitRootLogin e X11Forwarding. Os valores no desativam autenticação SSH por senha, acesso SSH direto como root e encaminhamento gráfico X11, respectivamente. SSH é o protocolo de acesso remoto criptografado; root é a conta administrativa; X11 encaminha janelas gráficas pela conexão.

UFW: default, deny, allow, limit e --force

UFW (“Uncomplicated Firewall”) é a interface simples do firewall do Ubuntu. default deny incoming bloqueia por padrão conexões que chegam ao servidor; default allow outgoing permite por padrão conexões iniciadas pelo servidor. limit ssh permite SSH, mas reduz tentativas repetidas de conexão do mesmo endereço. --force faz ufw enable ativar o firewall sem pedir confirmação. in em regras posteriores significa tráfego de entrada; ssh identifica a regra/serviço SSH.

systemctl restart ssh e Fail2ban

restart para e inicia novamente o serviço ssh, fazendo-o reler a configuração alterada. Fail2ban monitora registros de autenticação e bloqueia temporariamente origens com repetidas tentativas malsucedidas. apt-get install -y fail2ban instala o pacote; systemctl enable --now fail2ban configura início automático e inicia o serviço já nesta sessão.

unset PYTHONWARNINGS e reboot

PYTHONWARNINGS="ignore::SyntaxWarning" é uma variável de ambiente lida pelo Python: pede para ignorar avisos da categoria SyntaxWarning durante a instalação do Fail2ban. Um aviso de sintaxe aponta para construções de código Python suspeitas, mas não necessariamente impede sua execução. Os dois-pontos separam os campos da regra de filtro; o campo da mensagem foi deixado vazio. unset remove a variável do ambiente do shell depois da instalação. reboot reinicia todo o sistema operacional; a conexão SSH cai e é preciso aguardar a máquina voltar antes de reconectar.
