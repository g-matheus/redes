Atividade 1 • Servidor LAMP

Servidor web completo (LAMP) usando shell scripts

Script criado para a imagem Canonical Ubuntu 24.04, build 2026.09.18-0, na Oracle Cloud Infrastructure (OCI). Outras versões de Linux e provedores de nuvem podem exigir ajustes.

Execute o script completo, ele criará outros cinco scripts .sh e um setup.conf em ~. Após executar todos os scripts, você precisará publicar o site no segundo subdomínio manualmente, via SCP.

setup.confDomínio, subdomínio e repositório. server-hardening.shSSH, firewall e atualizações. apache2.shApache e VirtualHosts. tls-apache2.shCertificados com Certbot. mysql-php.shMySQL e PHP. deploy-subdomain1.shClona o site no primeiro subdomínio. Publicação no subdomínio 2Envia um template web via SCP.

Preparação

Tenha Ubuntu Server, acesso SSH com sudo, IP público e domínio. Aponte os registros DNS do domínio, www e dos dois subdomínios para o IP público do servidor. Libere as portas TCP 80/443 na Oracle Cloud Infrastructure.

Edite setup.conf com seus domínios e URL Git.

Gere os scripts a partir da home (~)

Via SSH, crie ~/generate-scripts.sh seguindo os passos abaixo:

  1. Acesse a homeExecute cd ~
  2. Crie o geradorExecute nano generate-scripts.sh e cole o script completo
  3. Gere os arquivosExecute bash ~/generate-scripts.sh
  4. Edite a configuraçãoAtualize ~/setup.conf com seus domínios e URL Git caso necessário.
Comandos para preparar os arquivos na hometerminal
cd ~
nano generate-scripts.sh
# Cole e salve o script gerador completo
bash ~/generate-scripts.sh

Depois, execute cada script gerado com sudo.

Ordem sugerida após editar setup.confexecutar da home
cd ~
sudo ./server-hardening.sh
# Aguarde a reinicialização e reconecte via SSH:
sudo ./apache2.sh
# Aguarde a reinicialização e reconecte via SSH:
sudo ./tls-apache2.sh
sudo ./mysql-php.sh
# Aguarde a reinicialização e reconecte via SSH:
sudo ./deploy-subdomain1.sh

Mantenha os scripts e setup.conf no mesmo diretório.

server-hardening.sh, apache2.sh e mysql-php.sh reiniciam o servidor. Aguarde a máquina voltar e reconecte via SSH antes do próximo script.

Script gerador completo

generate-scripts.sh 
#!/bin/bash
# Oracle Cloud Canonical Ubuntu 24.04 Image 2026.09.18-0 setup
# 1) Open ports 443 and 80 on Oracle Cloud Infrastructure:
#       Primary VNIC -> Subnet -> Security List -> Security Rules -> Add Ingress Rule
# 2) Set DNS records:
#       Name      Type   Content
#       @         A      Server IP
#       www       A      Server IP
#       docs      A      Server IP
#       template  A      Server IP

set -Eeuo pipefail
export DEBIAN_FRONTEND=noninteractive

echo "==> Generating scripts..."
echo "-> Generating setup.conf..."
cat << 'OUTER_EOF' > setup.conf
DOMAIN_NAME=m7.gs
SUBDOMAIN1=docs
SUBDOMAIN2=template
SUBDOMAIN1_SITE_REPO_URL="https://github.com/g-matheus/redes.git"
OUTER_EOF
chmod 640 setup.conf

# ========================================
# Updates and firewall
echo "-> Generating server-hardening.sh..."
cat << 'OUTER_EOF' > server-hardening.sh
#!/bin/bash

set -Eeuo pipefail
export DEBIAN_FRONTEND=noninteractive

echo "==> Updating packages..."
echo
apt-get update
apt-get upgrade -y
echo
echo "==> Configuring automatic updates..."
echo
apt-get install -y unattended-upgrades
cat > /etc/apt/apt.conf.d/20auto-upgrades <<'EOF'
APT::Periodic::Update-Package-Lists "1";
APT::Periodic::Unattended-Upgrade "1";
EOF
systemctl enable --now apt-daily.timer
systemctl enable --now apt-daily-upgrade.timer
echo
echo "==> Configuring SSH hardening..."
echo
sed -i -E "s/^#?PasswordAuthentication.*/PasswordAuthentication no/" "/etc/ssh/sshd_config"
sed -i -E "s/^#?PermitRootLogin.*/PermitRootLogin no/" "/etc/ssh/sshd_config"
sed -i -E "s/^#?X11Forwarding.*/X11Forwarding no/" "/etc/ssh/sshd_config"
echo
echo "==> Configuring Firewall (UFW)..."
echo
apt-get install -y ufw
ufw default deny incoming
ufw default allow outgoing
ufw limit ssh
ufw --force enable
echo
echo "==> Restarting SSH service..."
echo
systemctl restart ssh
echo
echo "==> Installing Fail2ban..."
echo
export PYTHONWARNINGS="ignore::SyntaxWarning"
apt-get install -y fail2ban
systemctl enable --now fail2ban
unset PYTHONWARNINGS
echo
echo "==> Done! Restarting server ..."
reboot
OUTER_EOF
chmod 740 server-hardening.sh

# ========================================
# Apache
echo "-> Generating apache2.sh..."
cat << 'OUTER_EOF' > apache2.sh
#!/bin/bash

set -Eeuo pipefail
export DEBIAN_FRONTEND=noninteractive

source "$(dirname "$0")/setup.conf"

echo "==> Installing Apache2 ..."
echo
apt-get install -y apache2
echo "-> Configuring global ServerName ..."
tee /etc/apache2/conf-available/servername.conf > /dev/null <<EOF
ServerName $DOMAIN_NAME
EOF
a2enconf servername
systemctl reload apache2
echo "==> Allowing ports 80 and 443 in UFW for Apache2 ..."
echo
ufw allow in "Apache Full"
echo
echo
echo "==> Configuring sites in Apache2 ..."
echo
echo "-> Removing default Apache sites ..."
a2dissite 000-default.conf default-ssl.conf
rm -f /etc/apache2/sites-available/000-default.conf
rm -f /etc/apache2/sites-available/default-ssl.conf
rm -rf /var/www/html
echo "-> Configuring $DOMAIN_NAME ..."
mkdir -p "/var/www/$DOMAIN_NAME"
tee "/etc/apache2/sites-available/$DOMAIN_NAME.conf" > /dev/null <<EOF
<VirtualHost *:80>
    ServerName $DOMAIN_NAME
    ServerAlias www.$DOMAIN_NAME
    DocumentRoot /var/www/$DOMAIN_NAME

    ErrorLog \${APACHE_LOG_DIR}/${DOMAIN_NAME}_error.log
    CustomLog \${APACHE_LOG_DIR}/${DOMAIN_NAME}_access.log combined
</VirtualHost>
EOF
echo "-> Configuring $SUBDOMAIN1.$DOMAIN_NAME ..."
mkdir -p "/var/www/$SUBDOMAIN1.$DOMAIN_NAME"
tee "/etc/apache2/sites-available/$SUBDOMAIN1.$DOMAIN_NAME.conf" > /dev/null <<EOF
<VirtualHost *:80>
    ServerName $SUBDOMAIN1.$DOMAIN_NAME
    DocumentRoot /var/www/$SUBDOMAIN1.$DOMAIN_NAME

    ErrorLog \${APACHE_LOG_DIR}/${SUBDOMAIN1}.${DOMAIN_NAME}_error.log
    CustomLog \${APACHE_LOG_DIR}/${SUBDOMAIN1}.${DOMAIN_NAME}_access.log combined
</VirtualHost>
EOF
echo "-> Configuring $SUBDOMAIN2.$DOMAIN_NAME ..."
mkdir -p "/var/www/$SUBDOMAIN2.$DOMAIN_NAME"
tee "/etc/apache2/sites-available/$SUBDOMAIN2.$DOMAIN_NAME.conf" > /dev/null <<EOF
<VirtualHost *:80>
    ServerName $SUBDOMAIN2.$DOMAIN_NAME
    DocumentRoot /var/www/$SUBDOMAIN2.$DOMAIN_NAME

    ErrorLog \${APACHE_LOG_DIR}/${SUBDOMAIN2}.${DOMAIN_NAME}_error.log
    CustomLog \${APACHE_LOG_DIR}/${SUBDOMAIN2}.${DOMAIN_NAME}_access.log combined
</VirtualHost>
EOF
echo "-> Enabling sites ..."
a2ensite "$DOMAIN_NAME.conf"
a2ensite "$SUBDOMAIN1.$DOMAIN_NAME.conf"
a2ensite "$SUBDOMAIN2.$DOMAIN_NAME.conf"
echo "-> Testing Apache configuration ..."
apache2ctl configtest
echo
echo "==> Done! Restarting server ..."
reboot
OUTER_EOF
chmod 740 apache2.sh

# ========================================
# TLS
echo "-> Generating tls-apache2.sh..."
cat << 'OUTER_EOF' > tls-apache2.sh
#!/bin/bash

set -Eeuo pipefail
export DEBIAN_FRONTEND=noninteractive

source "$(dirname "$0")/setup.conf"

echo "==> Configuring TLS ..."
echo
echo "-> Installing certbot ..."
apt install -y certbot python3-certbot-apache
echo "-> Configuring TLS certificates ..."
certbot --apache \
    --non-interactive \
    --agree-tos \
    --redirect \
    --register-unsafely-without-email \
    -d "$DOMAIN_NAME" \
    -d "www.$DOMAIN_NAME" \
    -d "$SUBDOMAIN1.$DOMAIN_NAME" \
    -d "$SUBDOMAIN2.$DOMAIN_NAME"
echo "-> Testing certificate renewal ..."
certbot renew --dry-run
systemctl reload apache2
echo
echo "==> Apache2 installation and TLS configuration completed successfully!"
OUTER_EOF
chmod 740 tls-apache2.sh

# ========================================
# MySQL and PHP

echo "-> Generating mysql-php.sh..."
cat << 'OUTER_EOF' > mysql-php.sh
#!/bin/bash

set -Eeuo pipefail
export DEBIAN_FRONTEND=noninteractive

source "$(dirname "$0")/setup.conf"

echo "==> Installing MySQL server..."
echo
apt-get install -y mysql-server

echo "==> Installing PHP..."
echo
apt-get install -y php libapache2-mod-php php-mysql
echo "-> Configuring index.php..."
tee /etc/apache2/mods-enabled/dir.conf > /dev/null << 'EOF'
<IfModule mod_dir.c>
    DirectoryIndex index.php index.html index.cgi index.pl index.xhtml index.htm
</IfModule>
EOF
tee /var/www/$DOMAIN_NAME/index.php > /dev/null << 'EOF'
<?php
phpinfo();
?>
EOF
echo "==> Done! Restarting server..."
reboot
OUTER_EOF
chmod 740 mysql-php.sh

# ========================================
# Deploy site on subdomain1

echo "-> Generating deploy-subdomain1.sh..."
cat << 'OUTER_EOF' > deploy-subdomain1.sh
#!/bin/bash

set -Eeuo pipefail
export DEBIAN_FRONTEND=noninteractive

source "$(dirname "$0")/setup.conf"
FULL_DOMAIN="${SUBDOMAIN1}.${DOMAIN_NAME}"
WEB_DIR="/var/www/${FULL_DOMAIN}"

echo "==> Cloning repository to ${WEB_DIR}..."
echo
git clone "$SUBDOMAIN1_SITE_REPO_URL" "$WEB_DIR"
echo "==> Done! Application deployed at http://${FULL_DOMAIN}"
OUTER_EOF
chmod 740 deploy-subdomain1.sh

# ========================================
echo "==> Setup scripts generated successfully!"
echo "-> Next step: run them with root privileges (e.g., sudo ./server-hardening.sh)"

Como o script gerador funciona

Cria cinco scripts e setup.conf na pasta atual. Não instala LAMP nem publica o site.

#!/bin/bash e comentários #

A primeira linha é o shebang: indica ao sistema que o arquivo deve ser interpretado pelo Bash, o shell de comandos usado aqui. Nas linhas seguintes, # inicia um comentário, que serve para leitura humana e não é executado. A exceção é o shebang na primeira linha, que informa qual interpretador usar ao executar o arquivo diretamente.

set -Eeuo pipefail

set ajusta opções do Bash. -e encerra após falha de um comando, com exceções em alguns contextos; -E faz o tratamento de erros ERR também valer em funções e subshells; -u trata variável não definida como erro; pipefail faz uma sequência ligada por | falhar se qualquer comando nela falhar, em vez de considerar só o último. Um subshell é um processo de shell filho.

export DEBIAN_FRONTEND=noninteractive

export marca uma variável para que comandos iniciados pelo shell também a recebam. DEBIAN_FRONTEND é consultada por ferramentas de instalação Debian/Ubuntu; noninteractive pede que não abram perguntas interativas durante a instalação. APT é o sistema que instala e atualiza pacotes do Ubuntu.

cat << 'OUTER_EOF' > arquivo

cat copia para a saída o texto que recebe. << inicia um heredoc (“here document”), um bloco de texto fornecido como entrada até encontrar uma linha isolada igual ao marcador. As aspas em 'OUTER_EOF' fazem o conteúdo ser gravado literalmente: variáveis como $DOMAIN_NAME não são expandidas enquanto o gerador roda. > redireciona a saída para um arquivo, criando-o ou substituindo seu conteúdo. O marcador é escolhido para não confundir o shell externo com heredocs dentro dos scripts que estão sendo gravados.

OUTER_EOF e EOF

São marcadores de encerramento de heredoc, escolhidos pelo autor e escritos sozinhos na linha final. OUTER_EOF encerra os blocos usados pelo gerador para escrever cada script; EOF aparece no conteúdo gerado e será interpretado somente quando aquele script for executado. Em heredoc sem aspas no marcador, o Bash expande variáveis e substituições de comando; com aspas, preserva o texto literalmente.

chmod 640 e chmod 740

setup.conf: leitura/escrita do dono e leitura do grupo (640). chmod altera permissões; cada dígito octal corresponde a dono, grupo e outros. Os valores combinam leitura (4), escrita (2) e execução (1). 640 significa dono ler/escrever, grupo ler e outros sem acesso. 740 significa dono ler/escrever/executar, grupo ler e outros sem acesso. A permissão de execução permite iniciar os arquivos de script diretamente; setup.conf apenas é lido pelos scripts e não precisa ser executável.

echo e diretório de saída

echo imprime uma mensagem e uma quebra de linha no terminal; as mensagens informam o progresso, não executam os comandos que aparecem no texto. Os redirecionamentos de cat criam os arquivos na pasta de trabalho atual, isto é, a pasta em que o terminal está posicionado. cd muda essa pasta; ~ é uma abreviação da pasta pessoal do usuário. Por isso as instruções executam cd ~ antes de gerar os arquivos.

bash, nano, sudo e ./

nano é um editor de texto no terminal; salve com Ctrl+O e saia com Ctrl+X. bash ~/generate-scripts.sh inicia o interpretador Bash e pede que ele leia esse arquivo; o til aponta para a pasta pessoal. sudo executa o comando seguinte com privilégios administrativos (root), necessários para instalar pacotes e alterar configurações do sistema. ./server-hardening.sh significa executar o arquivo na pasta atual: . representa a pasta atual e / separa o diretório do nome. O comando deve ser executado depois de entrar na pasta dos scripts.
