Servidor web completo (LAMP) usando shell scripts

Script criado para a imagem Canonical Ubuntu 24.04, build 2026.09.18-0, na Oracle Cloud Infrastructure (OCI). Outras versões de Linux e provedores de nuvem podem exigir ajustes.

Execute o script completo, ele criará outros cinco scripts .sh e um setup.conf em ~. Após executar todos os scripts, você precisará publicar o site no segundo subdomínio manualmente, via SCP.

Preparação

Tenha Ubuntu Server, acesso SSH com sudo, IP público e domínio. Aponte os registros DNS do domínio, www e dos dois subdomínios para o IP público do servidor. Libere as portas TCP 80/443 na Oracle Cloud Infrastructure.

Edite setup.conf com seus domínios e URL Git.

Se usar senha ao invés de chaves SSH, edite o script server-hardening.sh, removendo o SSH hardening.

Gere os scripts a partir da home (~)

Via SSH, crie ~/generate-scripts.sh seguindo os passos abaixo:

  1. Acesse a homeExecute cd ~
  2. Crie o geradorExecute nano generate-scripts.sh e cole o script completo
  3. Gere os arquivosExecute bash ~/generate-scripts.sh
Comandos para preparar os arquivos na hometerminal
cd ~
nano generate-scripts.sh
# Cole e salve o script gerador completo
bash ~/generate-scripts.sh

Depois, execute cada script gerado com sudo.

Ordem sugerida após editar setup.confexecutar da home
cd ~
sudo ./server-hardening.sh
# Aguarde a reinicialização e reconecte via SSH:
sudo ./apache2.sh
# Aguarde a reinicialização e reconecte via SSH:
sudo ./tls-apache2.sh
sudo ./mysql-php.sh
# Aguarde a reinicialização e reconecte via SSH:
sudo ./deploy-subdomain1.sh

Mantenha os scripts e setup.conf no mesmo diretório.

server-hardening.sh, apache2.sh e mysql-php.sh reiniciam o servidor. Aguarde a máquina voltar e reconecte via SSH antes do próximo script.

Como o script gerador funciona

Cria cinco scripts e setup.conf na pasta atual. Não instala LAMP nem publica o site.

#!/bin/bash e comentários #

A primeira linha é o shebang: indica ao sistema que o arquivo deve ser interpretado pelo Bash, o shell de comandos usado aqui. Nas linhas seguintes, # inicia um comentário, que serve para leitura humana e não é executado. A exceção é o shebang na primeira linha, que informa qual interpretador usar ao executar o arquivo diretamente.

set -Eeuo pipefail

set ajusta opções do Bash. -e encerra após falha de um comando, com exceções em alguns contextos; -E faz o tratamento de erros ERR também valer em funções e subshells; -u trata variável não definida como erro; pipefail faz uma sequência ligada por | falhar se qualquer comando nela falhar, em vez de considerar só o último. Um subshell é um processo de shell filho.

export DEBIAN_FRONTEND=noninteractive

export marca uma variável para que comandos iniciados pelo shell também a recebam. DEBIAN_FRONTEND é consultada por ferramentas de instalação Debian/Ubuntu; noninteractive pede que não abram perguntas interativas durante a instalação. APT é o sistema que instala e atualiza pacotes do Ubuntu.

cat << 'OUTER_EOF' > arquivo

cat copia para a saída o texto que recebe. << inicia um heredoc (“here document”), um bloco de texto fornecido como entrada até encontrar uma linha isolada igual ao marcador. As aspas em 'OUTER_EOF' fazem o conteúdo ser gravado literalmente: variáveis como $DOMAIN_NAME não são expandidas enquanto o gerador roda. > redireciona a saída para um arquivo, criando-o ou substituindo seu conteúdo. O marcador é escolhido para não confundir o shell externo com heredocs dentro dos scripts que estão sendo gravados.

OUTER_EOF e EOF

São marcadores de encerramento de heredoc, escolhidos pelo autor e escritos sozinhos na linha final. OUTER_EOF encerra os blocos usados pelo gerador para escrever cada script; EOF aparece no conteúdo gerado e será interpretado somente quando aquele script for executado. Em heredoc sem aspas no marcador, o Bash expande variáveis e substituições de comando; com aspas, preserva o texto literalmente.

chmod 640 e chmod 740

setup.conf: leitura/escrita do dono e leitura do grupo (640). chmod altera permissões; cada dígito octal corresponde a dono, grupo e outros. Os valores combinam leitura (4), escrita (2) e execução (1). 640 significa dono ler/escrever, grupo ler e outros sem acesso. 740 significa dono ler/escrever/executar, grupo ler e outros sem acesso. A permissão de execução permite iniciar os arquivos de script diretamente; setup.conf apenas é lido pelos scripts e não precisa ser executável.

echo e diretório de saída

echo imprime uma mensagem e uma quebra de linha no terminal; as mensagens informam o progresso, não executam os comandos que aparecem no texto. Os redirecionamentos de cat criam os arquivos na pasta de trabalho atual, isto é, a pasta em que o terminal está posicionado. cd muda essa pasta; ~ é uma abreviação da pasta pessoal do usuário. Por isso as instruções executam cd ~ antes de gerar os arquivos.

bash, nano, sudo e ./

nano é um editor de texto no terminal; salve com Ctrl+O e saia com Ctrl+X. bash ~/generate-scripts.sh inicia o interpretador Bash e pede que ele leia esse arquivo; o til aponta para a pasta pessoal. sudo executa o comando seguinte com privilégios administrativos (root), necessários para instalar pacotes e alterar configurações do sistema. ./server-hardening.sh significa executar o arquivo na pasta atual: . representa a pasta atual e / separa o diretório do nome. O comando deve ser executado depois de entrar na pasta dos scripts.
